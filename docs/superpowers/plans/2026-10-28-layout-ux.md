# Layout and UX Improvements Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Resizable side/bottom panel, an arrow-key "trip" between nearby cameras, and a System/Light/Dark theme (including the map) for the CCTV Jogja web app.

**Architecture:** Pure logic in new `web/src/lib/` modules (`theme.ts`, `size.ts`, `trip.ts`) with unit tests, wired into `App.svelte`, which owns all state (as it does today). Colours move to CSS custom properties in `app.css` keyed on `<html data-theme>`. One generic `Resizer.svelte` handle serves both the desktop divider and the mobile grab bar. `MapView.svelte` swaps OpenFreeMap styles and re-adds its layers on `style.load`.

**Tech Stack:** Svelte 5 (runes), TypeScript, MapLibre GL 6, Vitest + @testing-library/svelte (jsdom).

**Spec:** `docs/superpowers/specs/2026-10-28-layout-ux-design.md`

## Global Constraints

- No new dependencies. Svelte 5 runes, match existing style (2-space indent, `interface Props`, `$props()`, `on*` callback props).
- Run everything from `web/` with Node from `web/.nvmrc` and `pnpm`:
  `export NVM_DIR="$HOME/.nvm"; . "$NVM_DIR/nvm.sh"; nvm use`
- `pnpm test` and `pnpm check` must pass after every task.
- Storage is always accessed through `Storage | null` and wrapped in try/catch, like `lib/liveness.ts`; a blocked/absent storage must never break the app.
- localStorage keys: `cctv-theme` (`'light' | 'dark'`, absent = System), `cctv-panel-width` (px), `cctv-sheet-height` (fraction of viewport height).
- Map styles: light `https://tiles.openfreemap.org/styles/liberty`, dark `https://tiles.openfreemap.org/styles/dark`.
- Breakpoint stays `max-width: 640px`.
- The Wall (`Wall.svelte`, `WallTile.svelte`) is not themed; leave their colours alone.

## Review Focus

1. **No `matchMedia` / blocked storage** (jsdom, privacy modes): the app must load in light/System without throwing. → Task 1 tests `loadThemeChoice(null)` and garbage values; Task 3 App test runs with jsdom's missing `matchMedia`.
2. **Stored size larger than the current window** (dragged wide on a big monitor, reopened on a laptop): the map keeps ≥320px and the stored value is not overwritten. → Task 5 `clampSidebar` tests; Task 6 App test.
3. **Corrupt stored sizes** (`'abc'`, negative, `NaN`): fall back to defaults. → Task 5 `loadSize` tests.
4. **`↓` with nothing left to visit** (one visible camera, or every visible camera visited): no-op, no crash, no "Next ↓" row. → Task 7 tests.
5. **Arrow keys while focus is in an input, with modifiers, or auto-repeating**: ignored, and the page's default scroll is untouched. → Task 7 `tripKey` tests.

- Consumes: `distanceMeters` from `lib/geo.ts`, `Camera` type.
- Produces:
  - `interface Trip { trail: string[]; visited: string[] }` — last of `trail` is the current camera
  - `startTrip(id: string): Trip` → `{ trail: [id], visited: [id] }`
  - `nextTarget(trip: Trip, cams: Camera[], current: Camera): Camera | null` — nearest to `current` among `cams` whose id is not in `visited` (and not `current`); `null` if none
  - `stepForward(trip: Trip, id: string): Trip` — append to `trail`, add to `visited`
  - `stepBack(trip: Trip): Trip | null` — `null` if `trail.length < 2`, else `trail` without its last item; `visited` unchanged

  - `stepForward` to B, then `nextTarget(trip, all, B)` is C (not A — no bounce); then D; then `null` once everything is visited.
  - single visible camera: `nextTarget(startTrip('A'), [A], A) === null`.
  - filters: `nextTarget(startTrip('A'), [A, C, D], A)` is C.
  - `stepBack(startTrip('A')) === null`; after A→B→C, `stepBack` gives `trail` `['A','B']` and `visited` still contains C; `nextTarget` from B is then D.
  - `tripKey`: `ArrowDown` → `'next'`, `ArrowUp` → `'back'`, `'ArrowLeft'`/`'j'` → `null`; `repeat: true` → `null`; any of meta/ctrl/alt → `null`; `target` an `<input>`, `<textarea>`, or `<select>` element → `null`.
